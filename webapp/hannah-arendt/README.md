# 영화 한나 아렌트 활동 기록 웹앱

학교 구글 계정으로 접속하여 영화 활동을 작성하고, 교사가 선택한 제출본을 동아리 구성원과 함께 읽는 Google Apps Script 웹앱입니다. 『인간의 조건』 읽기를 위한 선행 활동과 아렌트의 중심 고민 탐색을 목적으로 합니다.

## 작성 문항

1. 인상적인 장면
2. 영화를 보면서 들었던 질문과 나의 답
   - 친구들에게 던질 질문과 그 질문에 대한 자신의 답을 한 쌍으로 작성합니다.
   - 처음에는 한 쌍을 제공하며, 질문과 답 추가 버튼으로 최대 10쌍까지 늘릴 수 있습니다.
3. 이 영화 속 장면과 한나 아렌트의 사상이 연결되는 지점은?
4. 향후 더 알아보고 싶은 점
   - 다음 활동인 『인간의 조건』에서 더 탐구하고 싶은 점을 간단히 적습니다. 선택 항목입니다.

## 화면과 운영

- 나의 활동 기록: 개인별 누적 기록, 수정, 제출 이력, 교사 피드백을 확인합니다.
- 활동 작성하기: 제목과 활동일을 지정하고 네 문항을 작성합니다. 자동 저장과 수동 저장을 지원합니다. 새 기록을 만들면 기존 기록과 별도로 누적됩니다.
- 다른 친구의 생각 보기: 교사가 공유한 제출본의 선택된 항목과 학생 이름만 표시합니다.
- 교사 대시보드: 모든 저장 기록을 조회하고, 검색·상태 필터·피드백·구성원 승인·CSV 내려받기를 이용합니다.

이번 네 문항의 저장 내용은 학생 본인과 교사가 볼 수 있습니다. 교사에게 제출하기 전에도 교사가 작성 중인 기록을 확인할 수 있다는 점을 작성 화면에 안내합니다. 개인 비공개 성찰일지는 이번 버전에 포함하지 않습니다.

교사는 제출본에서 공유할 항목을 선택하고 미리보기를 확인한 뒤 공유합니다. 학생이 나중에 수정해도 이미 공유된 제출본은 그대로 유지됩니다. 교사가 최신 제출본을 다시 공유해야 공유 내용이 바뀝니다. 공유를 해제해도 학생의 원본과 제출 이력은 보존됩니다. 학교 이메일, 학번, 교사 피드백은 친구 화면에 포함되지 않습니다.

## 설치

가장 간단한 방식은 `dist/한나아렌트_웹앱_Code.gs`를 사용하는 것입니다.

1. `cnsa.hs.kr` 학교 구글 계정으로 Google Apps Script에서 새 프로젝트를 만듭니다.
2. 기본 `Code.gs`의 내용을 `dist/한나아렌트_웹앱_Code.gs` 전체 내용으로 바꿉니다. 이 파일에는 화면까지 포함되어 있으므로 HTML 파일을 따로 만들 필요가 없습니다.
3. 프로젝트 설정에서 매니페스트 파일 표시를 켜고, `appsscript.json`을 함께 제공한 내용으로 바꿉니다.
4. 함수 목록에서 `install_`을 선택해 한 번 실행합니다. Google 권한 요청 내용을 확인하고 승인합니다. 실행한 학교 계정이 담당 교사로 등록되며 저장용 스프레드시트가 생성됩니다. 다시 실행해도 기존 저장소는 유지됩니다.
5. 배포 → 새 배포 → 웹 앱을 선택합니다. 실행 사용자는 배포한 교사, 접근 가능 사용자는 같은 학교 조직의 사용자로 설정합니다. 매니페스트의 값은 `USER_DEPLOYING`, `DOMAIN`입니다.
6. 배포된 `/exec` 주소로 교사 계정과 학생 계정 각각 접속하여 확인합니다. 처음 접속한 학생은 이름과 학번을 입력하고 교사 승인 후 이용합니다.
7. 배포 URL을 포털의 활동 링크에 연결합니다. 메뉴별 주소는 배포 URL 뒤에 `?view=write`, `?view=archive`, `?view=community`, `?view=teacher`를 붙여 사용합니다.

**저장용 스프레드시트와 Apps Script 편집 권한을 학생에게 공유하지 않습니다.** 학생은 웹앱만 이용합니다. 구성원의 계정은 `Session.getActiveUser().getEmail()`로 서버에서 확인하며, 클라이언트가 보낸 이메일이나 교사 역할을 신뢰하지 않습니다.

학교 정책이나 배포 설정 때문에 학생 이메일을 확인할 수 없으면 접근을 중단합니다. 이메일 직접 입력으로 우회하지 않습니다. 이 경우 같은 학교 조직으로 배포했는지 학교 Workspace 설정을 확인해야 합니다.

서버의 비공개 함수는 이름 끝에 `_`가 붙어 있어 `google.script.run`으로 호출할 수 없습니다. 초기 설정 함수도 비공개입니다. 편집기를 가진 교사만 실행합니다.

## 저장 구조

`Members`는 계정과 구성원 승인 상태, `Entries`는 최신 기록, `Versions`는 제출 이력, `Publications`는 교사가 공유한 스냅샷을 보관합니다. 스크립트 속성에는 `DB_ID`, `TEACHER_EMAILS`, `SCHOOL_DOMAIN`이 저장됩니다. 학생의 원문이나 계정 정보는 소스 저장소에 포함하지 않습니다.

서버는 저장 충돌을 검사합니다. 다른 창에서 수정한 기록을 이전 버전으로 덮어쓰지 않습니다. 네트워크 오류가 나면 입력을 유지하고, 화면에서 작성 중 내용을 JSON으로 내려받을 수 있습니다.

## 개발과 검증

- `node tests/verify.mjs`: 실제 `Code.gs`를 가상 Spreadsheet/Session 환경에서 실행하여 권한, 본인 기록 접근, 선택 항목 공유, 제출본 보존, 저장 충돌 등을 검사합니다.
- `node preview-server.mjs`: 가상 학생과 교사로 화면을 확인하는 로컬 전용 서버입니다. 학교 계정이나 실제 Google 저장소에 연결하지 않습니다. 실서비스로 배포하지 않습니다.
- `node build-bundle.mjs`: 단일 파일 배포본을 생성합니다.

소스를 여러 파일로 관리하려면 `Code.gs`, `Index.html`, `Styles.html`, `Client.html`, `appsscript.json`을 같은 Apps Script 프로젝트에 넣습니다. 단일 파일 방식과 여러 파일 방식을 한 프로젝트에 동시에 넣지 않습니다.

로컬 검증과 가상 자료 화면 검증은 실제 학교 계정으로 배포한 뒤의 접속 검증을 대신하지 않습니다. 실제 학생 접속 주소는 Apps Script 배포가 완료된 뒤 확정됩니다.
